# 课题卡（读者的研究背景）

> 说明：参赛者本人的研究方向与工程约束，由参赛者撰写，各案例共用。

## 研究方向
降低 LLM Agent 在长程执行（几十到上百步工具调用）中的幻觉：编造中间结果、引用不存在的文件/工具、早期错误被后续步骤当作事实传播。

## 为什么要复现别人的论文
我在做自己的方法，需要把相关论文当作**对比基线**：在我的环境里按论文设置重跑它的方法，或至少在它的基准上复现主表的一个数字，确认我的实现与论文一致后，再和我的方法比较。过去两次复现都是跑完才发现漏了设置（一次是判官模型版本不同，一次是论文用的是基准的一个子集），结果对不上，返工了一周。

## 我的条件
- 只能调用闭源前沿模型 API（Claude / Gemini / GPT 一类），不能训练或改权重；有一台 8×H200 服务器可跑开源模型推理。
- 单次复现预算约 200 美元 API 费用、一周工时。
- 不能联系作者之前就开工；可以查公开代码仓库。

## 我想从阅读中得到什么
1. 复现所需的设置论文给全了吗？哪些给了（在哪一页）、哪些没给、哪些前后矛盾？
2. 哪些缺口最可能让我复现不出来？去哪补？补不到时用什么替代值？
3. 最小复现方案：先复现哪个数字、多大规模、怎样算复现成功。
