# 复现配置清单（26 项）

每项在 `audit.jsonl` 中**恰好一行**，`item` 取下表 ID。`scan_config.py` 用"检索词"列逐页找候选位置；检索词只是线索，最终以原文为准。
不适用于本文的项写 `not_applicable` 并说明原因（例如纯推理论文的"训练超参"）。

| ID | 组 | 项目 | 要找到什么（复现时缺了会怎样） |
|---|---|---|---|
| M1 | 模型 | 被测/主模型 | 模型全名与版本号、快照日期或 API 版本；只有"GPT-4"类泛称算 partial |
| M2 | 模型 | 解码参数 | temperature、top-p、采样次数、是否开 thinking/reasoning effort |
| M3 | 模型 | 长度与步数上限 | max tokens、上下文长度、Agent 最大步数/轮数、超时 |
| M4 | 模型 | 辅助模型 | 判官、验证器、嵌入、检索、改写等非主模型的名称与版本 |
| D1 | 数据 | 基准/数据集 | 名称、版本或发布日期、来源 |
| D2 | 数据 | 实际使用的子集 | 划分、任务数/样本数、抽样方式与随机种子；数据统计量（长度、步数等）由哪种运行或哪个方法测得 |
| D3 | 数据 | 过滤与排除 | 去掉了哪些任务/样本及原因；失败任务如何计入 |
| D4 | 数据 | 数据可得性 | 是否公开、许可、获取方式；私有数据要注明 |
| P1 | 方法 | 方法流程 | 组件与执行顺序（算法框/流程图对应的文字），足以照着实现 |
| P2 | 方法 | 方法超参 | 候选数 N、k、阈值、迭代次数、权重等，以及取值依据 |
| P3 | 方法 | 提示词 | 系统/任务/判官提示是否全文给出及位置（附录节号） |
| P4 | 方法 | 运行环境与工具 | Agent 框架/harness、工具集、沙箱、外部服务（搜索 API 等） |
| P5 | 方法 | 基线配置 | 每个基线的实现来源与关键参数 |
| P6 | 方法 | 对照公平性 | 方法与基线是否同输入、同模型、同预算/同候选池 |
| E1 | 评测 | 指标与计分规则 | 指标定义、聚合方式（平均/通过率/任一次对即算对等） |

| E3 | 评测 | 重复与方差 | 运行次数、种子、标准差/置信区间是否报告 |

| R1 | 资源 | 算力 | GPU/CPU 型号数量、或"仅调用 API" |
| R2 | 资源 | 成本与耗时 | 每任务/总计的费用、token、时长，以及口径（是否含缓存、判官调用） |
| R3 | 资源 | 软件与时间 | 库版本、API 调用日期区间（闭源模型随时间漂移） |
| A1 | 产出 | 代码 | 是否公开、链接、许可；"将公开"算 partial |
| A2 | 产出 | 数据/轨迹/输出 | 生成数据、轨迹、预测结果是否公开 |
| T1 | 目标 | 要复现的主结果 | 主表核心数字及其模型/基准/变体/样本量（复现成功的判据） |
| T2 | 目标 | 消融与敏感性 | 关键消融或参数敏感性结果（判断哪个配置最不能错） |
| X1 | 风险 | 作者声明的局限与偏差 | 局限节、失败分析、已知偏差中影响复现的条目 |

## 状态取值
- `reported`：原文给出可直接使用的值。`quote` 必填，`value` 写出该值（值中的数字必须出现在 quote 里）。
- `partial`：原文提到但不足以复现（缺版本、缺具体数值、"见代码"等）。`quote` 必填，`missing` 写缺什么。
- `not_reported`：查过仍未找到。`searched` 必填：列出查过的页码与 `scan_config.py` 的候选页；`missing` 写复现时缺什么、`next_step` 写向谁/到哪里补。
- `conflicting`：原文不同位置给出不一致的值。`quote` 与 `quote2`（及 `page2`）都必填，`missing` 说明冲突。
- `not_applicable`：本文不涉及（`missing` 写原因）。
- `not_in_material`：**材料本身不完整**（截断/缺附录）导致无法判断，不能断言论文未报告。`searched` 与 `next_step` 必填。

一个项目有多个子值（如三个基准、两个模型）时：主行写最重要的，其余在 `value` 里用分号列出；每个数字仍须出现在 quote 中，必要时同一 item 增加 `M1b`、`M1c` 这样的补充行（item 仍写 `M1`）。
